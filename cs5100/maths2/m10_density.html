Density estimation and semi-supervised learning

Estimating a density without assuming a shape is "count the points near x, then divide by how many points and how much room you looked in". The histogram, the Parzen window and smooth kernels are three versions of that sentence, and the bandwidth h is one more flexibility knob. Semi-supervised K-means is Model 9 with a few labelled points to start from.

1. From “probability of a region” to \(k/(nV)\)

In plain words

Draw a small region around \(x\). Two ways to say how likely a new point is to land there: (a) the fraction of the data that did land there, \(k/n\); (b) the density at \(x\) times the size of the region, \(f(x)V\). Set them equal and solve for \(f(x)\). That’s the whole idea; everything else in this stage is a choice of region or a softer way of counting.

\[P \approx \frac{k}{n}\quad\text{and}\quad P \approx f(x)\,V\qquad\Longrightarrow\qquad \boxed{\hat f(x) = \frac{k}{nV}}\]

Symbol Meaning
\(n\) total number of observations
\(V\) size of the region around \(x\) (a length in 1D, an area in 2D, \(h^p\) for a cube of side \(h\) in \(p\) dimensions)
\(k\) number of observations inside the region

Why both pieces are needed. Dividing by \(n\) turns a count into a fraction. Dividing by \(V\) turns “fraction in this region” into “fraction per unit of length (area, volume)”, which is what a density is. Without \(V\) the answer would change just by measuring in centimetres instead of metres.

The histogram is the same formula with fixed bins: \(\hat f_H(x) = \frac{1}{n}\cdot\frac{\text{number of } x_i \text{ in the same bin as } x}{\text{bin width}}\) (slide 53).

Worked example 1: a histogram depends on where the bins start. Data \(\{4, 5, 5, 6, 12, 14, 15, 15, 16, 17\}\), \(n = 10\), bin width 5. Estimate \(\hat f(3)\).

bins start at bin holding 3 points in it \(\hat f(3)\)
0 \([0, 5)\) 4 \(\frac{1}{10\times5} = 0.02\)
2.5 \([2.5, 7.5)\) 4, 5, 5, 6 \(\frac{4}{10\times5} = 0.08\)

Same data, same width, a factor of 4 apart. That arbitrariness (plus jumps at bin edges, and the number of bins exploding in high dimensions) is why the slides move on to windows centred at \(x\) itself.

Try it with me. \(n = 20\) points in one dimension; an interval of length \(V = 2\) around \(x\) contains \(k = 2\) of them.

Give the fraction \(k/n\) and the density estimate \(k/(nV)\).

\(k/n = 2/20 = 0.1\). Then divide by \(V = 2\): \(\hat f(x) = 0.1/2 = 0.05\).

2. The Parzen window: a box centred at \(x\)

In plain words

Put a box of side \(h\) centred at the point where you want the density, count the data inside it, and use \(k/(nV)\) with \(V = h^p\). The kernel \(K\) is just a yes/no test: “is \(x_i\) inside the box?” Writing it with \(u = (x - x_i)/h\) means “how many box-widths away is \(x_i\)?”, and the box reaches half a width either side.

\[K(u) = \begin{cases}1 & \text{if } |u_j| \le \tfrac12 \text{ for every } j = 1,\dots,p\\ 0 & \text{otherwise}\end{cases}\qquad \boxed{\hat f(x) = \frac{1}{nh^p}\sum_{i=1}^n K\Big(\frac{x - x_i}{h}\Big)}\]

Symbol Meaning
\(h\) bandwidth: the side of the box
\(p\) number of dimensions; \(V = h^p\)
\(u_i = (x - x_i)/h\) the gap in units of \(h\)
\(\sum_i K(u_i)\) the count \(k\) of points in the box

In 1D the rule is simply: \(x_i\) counts if \(|x - x_i| \le h/2\), and a point exactly \(h/2\) away does count (\(\le\), not \(<\)).

Worked example 2 (slides 62 to 63). Data \(\{4, 5, 5, 6, 12, 14, 15, 15, 16, 17\}\), \(n = 10\), \(p = 1\), \(h = 4\), so the window is \(x \pm 2\) and \(nh = 40\).

\(x\) window points inside \(k\) \(\hat f(x) = k/40\)
3 \([1, 5]\) 4, 5, 5 3 0.075
10 \([8, 12]\) 12 (exactly on the edge: \(u = -0.5\), counts) 1 0.025
15 \([13, 17]\) 14, 15, 15, 16, 17 5 0.125

In kernel form for \(x = 10\): \(u_i = (10 - x_i)/4\) gives \(1.5, 1.25, 1.25, 1, -0.5, -1, -1.25, -1.25, -1.5, -1.75\); only \(u = -0.5\) passes \(|u| \le \frac12\).

Worked example 3: two dimensions, a square not a circle. Points \((1, 1), (2, 2), (3, 1), (5, 5), (2, 3)\), \(n = 5\). Estimate \(\hat f\) at \(x = (2, 2)\) with \(h = 2\), so \(V = h^2 = 4\) and the box is \([1, 3]\times[1, 3]\).

point \(|x_1 - x_{i1}| \le 1\)? \(|x_2 - x_{i2}| \le 1\)? inside?
(1, 1) 1, yes 1, yes yes
(2, 2) 0, yes 0, yes yes
(3, 1) 1, yes 1, yes yes
(5, 5) 3, no 3, no no
(2, 3) 0, yes 1, yes yes

\(k = 4\), so \(\hat f(2, 2) = \frac{4}{5 \times 4} = 0.2\). Note \((1, 1)\) is \(\sqrt2 \approx 1.41\) away, further than \(h/2 = 1\), but it’s in the square: the test is per coordinate.

Common mistakes with Parzen windows

  • Dividing by \(n\) only. You need \(nV = nh^p\). With \(h = 4\) in the example, forgetting \(h\) gives 0.3 instead of 0.075.
  • Window of half-width \(h\). The box has side \(h\), so it reaches \(h/2\) each side, not \(h\).
  • Excluding edge points. \(|u| \le \frac12\) includes \(|u| = \frac12\) exactly (the 12 in the \(x = 10\) row).
  • Using \(h\) instead of \(h^p\) in 2D or more: \(V = h^2\) for a square.
  • Using a circle (Euclidean distance) instead of the per-coordinate cube test.
  • Duplicates. \(\{5, 5\}\) are two observations: count both.

Try it with me. Same data as Worked example 2, \(h = 4\).

Estimate the density at \(x = 5\): give the count \(k\) and \(\hat f(5)\).

Window \([3, 7]\): 4, 5, 5, 6, so \(k = 4\) and \(\hat f(5) = 4/(10\times4) = 0.1\).

Now \(x = 9\).

Window \([7, 11]\) is empty, so \(\hat f(9) = 0\). A gap in the data gives a zero estimate, and the estimate jumps as soon as the window reaches a point: the blockiness the next section fixes.

3. Smooth kernels: bumps instead of boxes

In plain words

The box has two faults (slide 64): the estimate jumps whenever a point enters or leaves the window, and a point just inside counts as much as one at the centre. Fix both by replacing the yes/no box with a smooth bump that is tallest at gap 0 and fades with distance. Each data point now contributes a little, nearer points more. The formula keeps exactly the same shape.

\[\boxed{\hat f(x) = \frac{1}{nh^p}\sum_{i=1}^n K\Big(\frac{x - x_i}{h}\Big)},\qquad \text{Gaussian: } K(u) = (2\pi)^{-p/2}e^{-\frac12u^Tu};\quad \text{1D: } K(u) = \frac{1}{\sqrt{2\pi}}e^{-u^2/2}\]

The kernel must integrate to 1 (slide 65), and then so does \(\hat f\): each point contributes a bump of area \(\frac{1}{n}\). Other common shapes: the triangular kernel \(K(u) = \max(0, 1 - |u|)\), the Epanechnikov kernel. The Parzen box is the special case “flat bump”.

Handy values: \(\phi(0) = 0.3989\), \(\phi(0.5) = 0.3521\), \(\phi(1) = 0.2420\), \(\phi(2) = 0.0540\), where \(\phi(u) = \frac{1}{\sqrt{2\pi}}e^{-u^2/2}\).

Worked example 4: Gaussian kernel, two bandwidths. Data \(\{1, 2, 4\}\), \(n = 3\). Estimate \(\hat f(2)\).

\(h = 1\):

\(x_i\) \(u_i = (2 - x_i)/1\) \(K(u_i) = \phi(u_i)\)
1 1 0.2420
2 0 0.3989
4 −2 0.0540
total 0.6949

\(\hat f(2) = \frac{0.6949}{3\times1} = 0.2316\).

\(h = 2\):

\(x_i\) \(u_i = (2 - x_i)/2\) \(K(u_i)\)
1 0.5 0.3521
2 0 0.3989
4 −1 0.2420
total 0.9930

\(\hat f(2) = \frac{0.9930}{3\times2} = 0.1655\). The kernel values went up (gaps shrink when measured in bigger units), but dividing by the bigger \(h\) wins: a wider bandwidth spreads the same mass more thinly, so peaks come down.

Worked example 5: triangular kernel. Same data \(\{1, 2, 4\}\), \(h = 2\), \(x = 2\): \(u = 0.5, 0, -1\) give \(K = 0.5, 1, 0\). Sum 1.5, so \(\hat f(2) = 1.5/(3\times2) = 0.25\).

Common mistakes with smooth kernels

  • Plugging in the raw gap \(x - x_i\) instead of \((x - x_i)/h\).
  • Forgetting the \(\frac{1}{\sqrt{2\pi}}\) inside \(K\): \(e^{-u^2/2}\) alone at \(u = 0\) is 1, not 0.3989.
  • Double-dividing by \(h\): the \(\frac{1}{h}\) is outside the sum once. Don’t also put \(\sigma = h\) into the Gaussian’s constant.
  • Dropping far points with a Gaussian kernel: every point contributes, even if only 0.0001.

Try it with me. Data \(\{4, 6, 9\}\), Gaussian kernel, \(h = 1\), at \(x = 5\).

Give \(K\big((5 - 4)/1\big)\), the sum of the three kernel values, and \(\hat f(5)\). (For \(x_i = 9\), \(u = -4\) and \(\phi(-4) \approx 0.0001\).)

\(u = 1, -1, -4\) give \(0.2420, 0.2420, 0.0001\). Sum \(0.4841\); \(\hat f(5) = 0.4841/(3\times1) = 0.1614\).

4. Bandwidth is the bias-variance dial

In plain words

Small \(h\): you look only very close to \(x\), so the estimate follows the data’s every wiggle (and is zero in gaps): low bias, high variance. Large \(h\): you average over a wide stretch, so real bumps get smeared flat: high bias, low variance. The slides put it as “\(V\) large enough to contain enough points (variance), small enough that \(f\) is roughly constant inside it (bias)” (slide 58).

Worked example 6: \(\hat f(15)\) for the slide data as \(h\) changes.

\(h\) window \(k\) \(\hat f(15) = k/(10h)\)
1 \([14.5, 15.5]\) 2 0.2
2 \([14, 16]\) 4 0.2
4 \([13, 17]\) 5 0.125
8 \([11, 19]\) 6 0.075

As \(h\) grows, the window swallows the emptier stretch around 11 to 13 and the peak at 15 is flattened.

In kernel density estimation, what happens as the bandwidth \(h \to 0\)?

Each bump shrinks around its own point. Large \(h\) gives the opposite: one broad smear that hides the structure.

5. Semi-supervised K-means

In plain words

Labels are expensive, unlabelled data is cheap. If a few points come with labels (“seeds”), use them to start K-means in a sensible place: each cluster’s starting centre is the mean of the seeds with that label. Then two versions (slides, semi-supervised section):

  • Seeded K-means: seeds are used only for the starting centres. After that, run ordinary K-means on all the points; a seed may end up in a different cluster from its label.
  • Constrained K-means: same start, but seeds keep their labels in every assignment step. Only the unlabelled points are reassigned. (Seeds still count when computing the means.)

Worked example 7: seeded vs constrained, 1D. Seeds: \(1, 2\) labelled A; \(6, 12\) labelled B. Unlabelled: \(3, 4, 11, 13\).

Start: \(\mu_A = \frac{1 + 2}{2} = 1.5\), \(\mu_B = \frac{6 + 12}{2} = 9\).

Seeded.

step A B \(\mu_A\) \(\mu_B\)
assign to 1.5 / 9 1, 2, 3, 4 6, 11, 12, 13 2.5 10.5
assign to 2.5 / 10.5 1, 2, 3, 4, 6 (gap 3.5 vs 4.5) 11, 12, 13 3.2 12
assign to 3.2 / 12 no change 3.2 12

Seed 6 moved from B to A, which is allowed in seeded K-means.

Constrained. Same first step. At the second step, 6 is a B seed, so it stays in B even though 2.5 is nearer. The unlabelled points don’t move (4 is nearer 2.5, 11 and 13 nearer 10.5). Final: A \(= \{1, 2, 3, 4\}\), \(\mu_A = 2.5\); B \(= \{6, 11, 12, 13\}\), \(\mu_B = 10.5\).

Common mistakes in semi-supervised K-means

  • Starting centres from all the data instead of the seed means for each label.
  • Mixing up the two: seeded lets seeds move; constrained pins them.
  • Leaving seeds out of the means in constrained K-means: they’re pinned, not ignored.

Seeds \(1, 3\) labelled A and \(8, 10\) labelled B. Give the starting centres.

\((1 + 3)/2 = 2\) and \((8 + 10)/2 = 9\).

Stage test

Data \(\{4, 5, 5, 6, 12, 14, 15, 15, 16, 17\}\), Parzen window, \(h = 4\). Estimate \(\hat f(13)\).

Window \([11, 15]\): 12, 14, 15, 15, so \(k = 4\) and \(\hat f(13) = 4/40 = 0.1\).

Points \((0, 0), (1, 1), (1, -1), (3, 0)\) in 2D. Parzen window with \(h = 2\) at \(x = (0, 0)\). Estimate \(\hat f(0, 0)\).

The box is \([-1, 1]\times[-1, 1]\). \((0, 0)\) is inside; \((1, 1)\) and \((1, -1)\) have both gaps equal to \(1 = h/2\), so they are inside too; \((3, 0)\) is not. So \(k = 3\), \(V = h^2 = 4\), \(n = 4\): \(\hat f = 3/(4\times4) = 0.1875\).

Why does the Parzen-window formula divide by \(nh^p\) rather than by \(n\)?

\(k/(nV)\) with \(V = h^p\).

Which is the difference between seeded and constrained K-means?

Week 7 slides, semi-supervised K-means.

Past-paper style. Explain the two drawbacks of the Parzen window that motivate smooth kernels, and say what the bandwidth controls.

The Parzen estimate is discontinuous (it jumps when a point enters or leaves the window), and it weights every point inside the window equally regardless of how far it is from \(x\). A smooth kernel such as the Gaussian gives a continuous estimate and weights nearer points more. The bandwidth \(h\) controls smoothing: small \(h\) gives a spiky, high-variance estimate; large \(h\) a smooth but biased one that can hide real structure.
