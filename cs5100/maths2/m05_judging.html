1. The confusion matrix

In plain words

Sort every test point into one of four boxes by (truth, prediction). Every rate the course uses is “one box divided by a row total or a column total”. The trick is remembering which.

predicted + predicted − row total
truly + TP FN P = TP + FN
truly − FP TN N = FP + TN
Rate Formula Divides by Also called
true positive rate TP / P truly + sensitivity, recall, power
false positive rate FP / N truly − 1 − specificity, type I error rate
specificity TN / N truly − true negative rate
precision TP / (TP + FP) predicted + positive predictive value
accuracy (TP + TN) / (P + N) everything 1 − error rate

Worked example 1. TP = 40, FN = 10, FP = 20, TN = 130. So P = 50, N = 150, total 200.

rate working value
TPR (sensitivity) 40/50 0.8
FPR 20/150 0.133
specificity 130/150 0.867
precision 40/(40 + 20) 0.667
accuracy (40 + 130)/200 0.85
error rate (10 + 20)/200 0.15

Common mistakes

  • FPR = FP / (all predicted +). No: FPR divides by the truly negative row, N.
  • Precision vs TPR. Precision divides by the predicted-+ column; TPR by the truly-+ row.
  • High accuracy on unbalanced data. If 95% are negative, “always predict −” gets 95% accuracy and TPR 0. That’s why the week 3 lab balances the classes.

TP = 30, FN = 10, FP = 10, TN = 90. Give P (the number of truly positive points), the TPR, the FPR and the accuracy.

P = TP + FN = 40. TPR = 0.75, FPR = 0.1, accuracy = 120/140 = 0.857.

2. Thresholds, ROC and AUC

In plain words

A probabilistic classifier predicts + when its score passes a threshold \(t\). Lower \(t\): more positives, so TPR rises but so does FPR. The ROC curve plots (FPR, TPR) for every threshold. The AUC (area under it) has a lovely counting meaning: pick a random positive and a random negative; AUC is the chance the positive gets the higher score.

Worked example 2. Six test points, sorted by score:

score 0.9 0.8 0.7 0.6 0.4 0.3
label 1 1 0 1 0 0

ROC points (predict + when score \(\ge t\); P = N = 3):

\(t\) TP FP TPR FPR
above 0.9 0 0 0 0
0.9 1 0 0.333 0
0.8 2 0 0.667 0
0.7 2 1 0.667 0.333
0.6 3 1 1 0.333
0.4 3 2 1 0.667
0.3 3 3 1 1

AUC by counting pairs: for each positive, count the negatives it beats.

positive score beats negatives (0.7, 0.4, 0.3) count
0.9 all three 3
0.8 all three 3
0.6 0.4, 0.3 2
total 8 of 3 × 3 = 9

AUC \(= 8/9 = 0.889\). (The area under the staircase in the first table gives the same number.)

Common mistakes

  • Dividing by the number of points instead of the number of (positive, negative) pairs, \(P\times N\).
  • Ties count as half a win.
  • AUC 0.5 = random guessing; AUC below 0.5 means the scores are backwards.

Scores and labels: 0.95 (1), 0.85 (0), 0.7 (1), 0.5 (0), 0.4 (1), 0.2 (0). For each positive, how many negatives does it beat? Then the AUC.

Negatives 0.85, 0.5, 0.2. 0.95 beats 3; 0.7 beats 0.5 and 0.2 (2); 0.4 beats 0.2 (1). AUC \(= 6/9 = 0.667\).

3. Bias and variance: squared error

The expected test error at \(x_0\) splits into bias² + variance + noise (Toolkit 3). Flexible models have low bias, high variance; rigid ones the reverse. The test error is U-shaped in flexibility; the training error just keeps falling.

4. Comparing two algorithms: the binomial

In plain words

Algorithm 1 beat algorithm 0 on the test set. Was it skill or luck? Only the points where they disagree carry information. If they were equally good, each disagreement would be a fair coin flip. The p-value asks how often a fair coin would give a result at least this lopsided.

alg 1 correct alg 1 wrong
alg 0 correct (agree) \(n_{01}\): alg 0 wins
alg 0 wrong \(n_{10}\): alg 1 wins (agree)

\(N = n_{01} + n_{10}\); \(k = n_{10}\); \(p = P(Y \ge k)\) with \(Y\sim\text{Binomial}(N, \frac12)\), i.e. \(p = \frac{1}{2^N}\sum_{j=k}^N\binom Nj\). Reject “not better” at level \(\alpha\) if \(p \le \alpha\).

Worked example 3. Table: both correct 150, alg 0 right and alg 1 wrong 2, alg 0 wrong and alg 1 right 9, both wrong 20.

step working
discard agreements 150 + 20 points carry no information
\(N\), \(k\) \(N = 2 + 9 = 11\), \(k = 9\)
tail terms \(\binom{11}{9} = 55\), \(\binom{11}{10} = 11\), \(\binom{11}{11} = 1\); sum 67
p-value \(67/2^{11} = 67/2048 = 0.0327\)
decision \(0.0327 \le 0.05\): reject at 5%; \(> 0.01\): not at 1%

Common mistakes

  • \(N\) = test set size. Only disagreements.
  • One term instead of the tail. \(P(Y = 9)\) alone is \(55/2048\); the p-value adds 10 and 11 too.
  • Reading the table the wrong way round. Find the cell where the algorithm you’re testing is right and the other is wrong.

Alg 0 right / alg 1 wrong: 1. Alg 0 wrong / alg 1 right: 7. Both right: 80. Both wrong: 12. Give \(N\), \(k\) and the one-sided p-value.

\(N = 8\), \(k = 7\). \(\binom87 + \binom88 = 8 + 1 = 9\). \(p = 9/256 = 0.0352\): significant at 5%.
