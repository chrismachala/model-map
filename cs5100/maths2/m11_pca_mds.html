PCA, MDS and t-SNE

Week 8's three ways to draw high-dimensional data in two dimensions. PCA keeps the directions with the most variance; MDS places points so their distances match the originals in squared error; t-SNE matches neighbourhood probabilities. This stage runs a whole PCA by hand, from raw data to reconstruction error, then computes a stress and the pieces of t-SNE.

1. A whole PCA by hand

In plain words

PCA finds a new set of perpendicular axes for the data. The first axis points where the data is most spread out; each later one is the most spread-out direction perpendicular to the ones before. The recipe: centre the data, form the covariance matrix, find its eigenvectors (the axes, called loading vectors) and eigenvalues (the variance along each axis), then project each point onto the axes to get its scores.

\[\Sigma = \frac1n\sum_i(x_i - \bar x)(x_i - \bar x)^T,\qquad \Sigma\varphi_m = \lambda_m\varphi_m,\qquad \boxed{z_{im} = \varphi_m^T(x_i - \bar x)},\qquad \text{PVE}_m = \frac{\lambda_m}{\sum_j\lambda_j}\]

Symbol Meaning
\(\bar x\) the mean vector, subtracted first
\(\varphi_m\) the \(m\)th loading vector (unit length, perpendicular to the others)
\(\lambda_m\) the variance of the \(m\)th scores; \(\lambda_1 \ge \lambda_2 \ge \dots\)
\(z_{im}\) point \(i\)’s score on component \(m\): its coordinate along that axis
\(\sum_j\lambda_j\) total variance = the diagonal of \(\Sigma\) added up (\(= p\) for standardised data)

For a 2×2 matrix \(\begin{pmatrix}a & b\\b & a\end{pmatrix}\) (equal diagonal) the eigenvalues are \(a \pm b\) with directions \(\frac{1}{\sqrt2}(1, 1)\) and \(\frac{1}{\sqrt2}(1, -1)\).

Worked example 1: raw data to PVE. Points \((1, 2), (3, 4), (5, 8), (7, 6)\), \(n = 4\).

Step 1, centre. \(\bar x = \big(\frac{16}{4}, \frac{20}{4}\big) = (4, 5)\).

point centred \((x_1 - 4, x_2 - 5)\) \(c_1^2\) \(c_2^2\) \(c_1c_2\)
(1, 2) (−3, −3) 9 9 9
(3, 4) (−1, −1) 1 1 1
(5, 8) (1, 3) 1 9 3
(7, 6) (3, 1) 9 1 3
total (0, 0) 20 20 16

Step 2, covariance (divide by \(n = 4\)): \(\Sigma = \begin{pmatrix}5 & 4\\4 & 5\end{pmatrix}\).

Step 3, eigen: equal diagonal, so \(\lambda_1 = 5 + 4 = 9\) along \(\varphi_1 = \frac{1}{\sqrt2}(1, 1)\) and \(\lambda_2 = 5 - 4 = 1\) along \(\varphi_2 = \frac{1}{\sqrt2}(1, -1)\). Check: \(9 + 1 = 10 = 5 + 5\), the trace ✓.

Step 4, scores: \(z_{i1} = \frac{c_1 + c_2}{\sqrt2}\), \(z_{i2} = \frac{c_1 - c_2}{\sqrt2}\).

point \(z_{i1}\) \(z_{i2}\) \(z_{i1}^2\) \(z_{i2}^2\)
(1, 2) \(-6/\sqrt2 = -4.243\) 0 18 0
(3, 4) \(-2/\sqrt2 = -1.414\) 0 2 0
(5, 8) \(4/\sqrt2 = 2.828\) \(-2/\sqrt2 = -1.414\) 8 2
(7, 6) \(4/\sqrt2 = 2.828\) \(2/\sqrt2 = 1.414\) 8 2
average 0 0 9 1

The average squared score is the eigenvalue, as it should be. PVE of PC1 \(= 9/10 = 0.9\).

Common mistakes in a PCA by hand

  • Not centring before forming \(\Sigma\) or the scores. Raw coordinates squared give the “variance about the origin” (the same slip as squaring raw coordinates in a K-means SSE).
  • A loading vector that isn’t unit length: \((1, 1)\) instead of \(\frac{1}{\sqrt2}(1, 1)\) doubles every variance.
  • \(\frac1{n-1}\) vs \(\frac1n\): state which; the slides use \(\frac1n\).
  • PVE from standard deviations instead of variances (eigenvalues).
  • Worrying about signs: \(-\varphi\) is just as good, and flips every score’s sign.

Try it with me. Points \((0, 0), (2, 2), (4, 0), (2, -2)\).

Give the mean, then \(\Sigma_{11}\), \(\Sigma_{22}\) and \(\Sigma_{12}\) (divide by \(n\)).

Mean \((2, 0)\). Centred: \((-2, 0), (0, 2), (2, 0), (0, -2)\). \(\Sigma_{11} = (4 + 0 + 4 + 0)/4 = 2\), \(\Sigma_{22} = 2\), \(\Sigma_{12} = 0\) (every product has a zero). The data are a square: every direction has variance 2, so PCA has no preferred axis here.

2. Scores from loadings, and reconstruction

In plain words

Once you have the loading vectors, a point’s score is just a dot product: multiply each (centred, usually standardised) attribute by its loading and add. Going back, you rebuild the point from its first \(M\) scores; what you lose is the variance in the dropped components.

\[\boxed{\hat x_i = \bar x + \sum_{m=1}^{M}z_{im}\varphi_m},\qquad \frac1n\sum_i\|x_i - \hat x_i\|^2 = \sum_{m > M}\lambda_m\]

Worked example 2: rebuild a point from one component. From Worked example 1, the point \((5, 8)\) has \(z_1 = 2.828\).

\(\hat x = (4, 5) + 2.828\times\big(0.7071, 0.7071\big) = (4, 5) + (2, 2) = (6, 7)\).

Error \(= (5 - 6)^2 + (8 - 7)^2 = 2\), which is exactly \(z_2^2\). Averaging over the four points: \((0 + 0 + 2 + 2)/4 = 1 = \lambda_2\), the dropped eigenvalue.

Worked example 3: USArrests scores (slide 40). Loadings for Murder, Assault, UrbanPop, Rape: PC1 \((0.54, 0.58, 0.28, 0.54)\), PC2 \((-0.42, -0.19, 0.87, 0.17)\). A state with standardised values \((1, 0.5, -1, 0)\):

attribute \(x_j\) \(\varphi_{j1}x_j\) \(\varphi_{j2}x_j\)
Murder 1 0.54 −0.42
Assault 0.5 0.29 −0.095
UrbanPop −1 −0.28 −0.87
Rape 0 0 0
score $z_1 = $ 0.55 $z_2 = $ −1.385

PC1 is roughly “overall crime” (the three crimes load about equally), PC2 “urbanisation”. This state: a little above average crime, quite rural.

3. How many components? PVE, scree, eigenvalue-one

In plain words

There’s no single right answer (slide 33), so know all three rules. Threshold: keep the fewest components whose cumulative PVE passes a target like 80%. Scree plot: plot PVE against \(m\) and keep what’s left of the elbow. Eigenvalue-one (standardised data only): keep components with \(\lambda > 1\), since each original attribute has variance 1, so a component below 1 explains less than a single attribute.

Worked example 4. PCA on 6 standardised attributes gives \(\lambda = 2.7, 1.5, 0.9, 0.5, 0.3, 0.1\) (sum 6 ✓).

\(m\) \(\lambda_m\) PVE \(= \lambda_m/6\) cumulative
1 2.7 0.45 0.45
2 1.5 0.25 0.70
3 0.9 0.15 0.85
4 0.5 0.0833 0.9333
5 0.3 0.05 0.9833
6 0.1 0.0167 1

80% threshold: \(M = 3\) (first cumulative value above 0.8). Eigenvalue-one: \(M = 2\) (\(2.7\) and \(1.5\)). Scree: the drop flattens after \(m = 3\) or so. Different rules, different answers: say which you’re using.

For USArrests (slides, \(\frac1n\)): \(\lambda = 2.480, 0.990, 0.357, 0.173\), cumulative 62.0%, 86.8%, 95.7%, 100%. Eigenvalue-one gives \(M = 1\) here, but scikit-learn’s \(\frac1{n-1}\) variances make \(\lambda_2 = 1.010\) and \(M = 2\): a borderline case where the convention matters.

Common mistakes choosing M

  • Eigenvalue-one on unstandardised data: the “1” only means something when every attribute has variance 1.
  • Reading the threshold wrong: “above 0.8” at \(m = 3\) means keep 3, not 2.
  • Dividing by \(p\) instead of the total when the data aren’t standardised; the total is \(\sum\lambda_j\).
  • Not scaling attributes measured in different units: Assault (per 100,000, values in the hundreds) would dominate PC1 alone (slide 41).

4. MDS: match the distances, in squared error

In plain words

MDS forgets about axes. It places points \(\tilde x_i\) in 2D (or 1D) so that the distances between them are as close as possible to the original distances. “As close as possible” is squared error again, called the stress. There’s no formula for the answer, so it starts from random positions and improves them by gradient descent, which can land in a local minimum.

\[\boxed{\text{stress} = \sum_{i<j}\big(d(x_i, x_j) - d(\tilde x_i, \tilde x_j)\big)^2}\]

The slides write \(\sum_{i,j}\) over all ordered pairs, which counts every pair twice; the \(i<j\) version is half as big with the same minimiser. Say which.

Worked example 5 (week 8 notes). \(A = (0, 0)\), \(B = (3, 0)\), \(C = (0, 4)\); a 1D embedding at \(\tilde A = 0\), \(\tilde B = 2.5\), \(\tilde C = -3.5\).

pair original \(d\) embedded \(\tilde d\) \((d - \tilde d)^2\)
AB 3 2.5 0.25
AC 4 3.5 0.25
BC 5 6 1
stress 1.5

The embedded BC is \(|2.5 - (-3.5)| = 6\). Over ordered pairs the stress would be 3.

Common mistakes with the stress

  • Comparing coordinates instead of distances: MDS doesn’t care where the points sit, only how far apart.
  • Signed gaps on the line: embedded distances are absolute values.
  • Squared distances inside: the stress uses plain distances, squared after subtracting.
  • Mixing \(i<j\) and ordered pairs (factor 2).

Try it with me. \(A = (0, 0)\), \(B = (3, 0)\), \(C = (0, 4)\) again, now embedded at \(0, 3, -4\).

Give the embedded distance BC and the stress (over \(i<j\)).

AB: \(3\) vs \(3\); AC: \(4\) vs \(4\); BC: \(5\) vs \(|3 - (-4)| = 7\). Stress \(= 0 + 0 + (5 - 7)^2 = 4\).

\(A = (0, 0)\), \(B = (1, 0)\), \(C = (1, 1)\), embedded on a line at \(0, 1, 2\). Give the stress over \(i<j\).

Original: AB 1, AC \(\sqrt2 = 1.4142\), BC 1. Embedded: 1, 2, 1. Stress \(= 0 + (1.4142 - 2)^2 + 0 = 0.3431\).

5. t-SNE: Gaussian neighbours, \(t\) neighbours, KL

In plain words

t-SNE turns distances into “how likely is \(j\) to be \(i\)’s neighbour” probabilities, once in the original space with a Gaussian bump and once in 2D with a heavier-tailed \(t\) bump, then moves the 2D points by gradient descent until the two sets of probabilities match, measured by KL divergence. The heavy tail lets points that aren’t neighbours sit far apart in 2D, so clusters separate.

\[s(x, x') = e^{-\|x - x'\|^2/2\sigma^2},\qquad s'(z, z') = \frac{1}{1 + \|z - z'\|^2},\qquad p_{ij} = \frac{s_{ij}}{\sum s},\ q_{ij} = \frac{s'_{ij}}{\sum s'}\]

\[\boxed{\text{KL}(P\,\|\,Q) = \sum p_{ij}\log\frac{p_{ij}}{q_{ij}} = \underbrace{-\sum p_{ij}\log q_{ij}}_{\text{cross-entropy}} - \underbrace{\Big(-\sum p_{ij}\log p_{ij}\Big)}_{\text{fixed by the data}}}\]

Worked example 6: why the \(t\) tail matters. Three points with pairwise distances \(d_{12} = 1\), \(d_{13} = 3\), \(d_{23} = 2\), \(\sigma = 1\).

pair \(d\) Gaussian \(e^{-d^2/2}\) \(p\) \(t\): \(\frac{1}{1 + d^2}\) \(q\) (same distances)
1–2 1 0.6065 0.8055 0.5 0.625
1–3 3 0.0111 0.0148 0.1 0.125
2–3 2 0.1353 0.1797 0.2 0.25
sum 0.7530 1 0.8 1

Even if the 2D map kept every distance exactly, the \(t\) similarity gives the far pair 1–3 far more probability (\(0.125\) vs \(0.0148\)). To shrink \(q_{13}\) towards \(p_{13}\), t-SNE pushes 3 further away in 2D: that’s the cluster-separating effect. Here \(\text{KL} = 0.1135\).

Worked example 7: KL and cross-entropy. \(P = (0.5, 0.3, 0.2)\), \(Q = (0.4, 0.4, 0.2)\).

\(\text{KL} = 0.5\ln\frac{0.5}{0.4} + 0.3\ln\frac{0.3}{0.4} + 0.2\ln1 = 0.1116 - 0.0863 + 0 = 0.0253\).

Cross-entropy \(-\sum p\ln q = 1.0549\); entropy of \(P\) \(= 1.0297\); difference \(0.0253\) ✓. Only the cross-entropy depends on the embedding, so minimising KL = minimising cross-entropy (as in logistic regression, toolkit stage 9).

Common mistakes with t-SNE

  • Forgetting to normalise the similarities into probabilities.
  • The 1 in the numerator of the \(t\) similarity: some PDF viewers drop it from slide 52.
  • KL direction: it’s \(\text{KL}(P\|Q)\), the original-space \(P\) first. KL isn’t symmetric.
  • Over-reading the plot: cluster sizes and gaps between clusters mean little; t-SNE can’t project new points; results depend on the random start and \(\sigma\) (perplexity).

Two points at distance 1, \(\sigma = 1\). Give the Gaussian similarity and the \(t\) similarity.

\(e^{-1/2} = 0.6065\) and \(\frac{1}{1 + 1} = 0.5\).

Stage test

Centred data \((2, 2), (-2, -2), (1, -1), (-1, 1)\). Give \(\lambda_1\), \(\lambda_2\) (divide by \(n\)) and the PVE of PC1.

\(\Sigma_{11} = (4 + 4 + 1 + 1)/4 = 2.5\), \(\Sigma_{22} = 2.5\), \(\Sigma_{12} = (4 + 4 - 1 - 1)/4 = 1.5\). Equal diagonal: \(\lambda = 2.5 \pm 1.5 = 4, 1\). PVE \(= 4/5 = 0.8\).

Data with \(\bar x = (0, 0)\) and loading vectors \(\varphi_1 = \frac{1}{\sqrt2}(1, 1)\), \(\varphi_2 = \frac{1}{\sqrt2}(1, -1)\). Reconstruct the point \((3, 1)\) from PC1 only and give the squared reconstruction error.

\(z_1 = \frac{3 + 1}{\sqrt2} = 2.828\), \(\hat x = 2.828\times(0.7071, 0.7071) = (2, 2)\). Error \((3 - 2)^2 + (1 - 2)^2 = 2\), which equals \(z_2^2 = \big(\frac{3 - 1}{\sqrt2}\big)^2 = 2\).

Minimising the KL divergence \(\sum p_{ij}\log(p_{ij}/q_{ij})\) over the embedding is the same as minimising…

Same trick as logistic regression’s loss: the original distribution’s own term is a constant.

You run PCA on unstandardised data where one attribute is measured in the hundreds and the rest are between 0 and 1. What happens?

PCA maximises variance, and variance depends on units. Standardise first when units differ (slide 41).

Past-paper style. Compare PCA, MDS and t-SNE for visualising the digits data: what each optimises, and one strength and one weakness of each.

PCA: maximises the variance of linear projections (equivalently minimises squared reconstruction error); fast, gives interpretable loadings, a PVE and can transform new points; but linear, so curved or clustered structure may look like “a mess” (digits: first two PCs explain 28.5%). MDS: minimises the stress between original and embedded distances by gradient descent; works from a distance table alone; but slow, local minima, and still poor on digits. t-SNE: minimises KL between Gaussian neighbour probabilities and heavy-tailed \(t\) probabilities in 2D; separates the ten digit clusters cleanly; but only for visualisation, gaps and sizes are not meaningful, depends on perplexity and the random start, and can’t embed new points.
