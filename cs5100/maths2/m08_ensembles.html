Bagging, random forests and boosting

Week 6 builds strong models out of many trees. Bagging and random forests grow deep trees independently on bootstrap samples and average them, attacking variance. Boosting grows small trees one after another, each fixing what the last ones got wrong, attacking bias. This stage runs two rounds of boosting by hand and lines the three methods up side by side.

1. Bagging and random forests

In plain words

Bagging = bootstrap aggregating: make \(B\) bootstrap samples, grow a deep tree on each (low bias, high variance), and average their predictions (or majority vote). Averaging cuts the variance. Random forests add one twist: at every split, each tree may only consider a random subset of \(m\) of the \(p\) inputs. That stops all trees from splitting on the same strong input first, makes them less alike (lower \(\rho\)), and so lowers the variance floor.

bagging random forest
samples bootstrap bootstrap
inputs tried at each split all \(p\) random \(m\): \(\approx\sqrt p\) (classification), \(\approx p/3\) (regression)
trees deep, unpruned deep, unpruned
combine average / vote average / vote
more trees \(B\) never overfits never overfits
\(m = p\) is just bagging

Worked example 1: why decorrelating helps. Each tree’s variance \(\sigma^2 = 9\), \(B = 100\).

method \(\rho\) \(\rho\sigma^2 + \frac{1 - \rho}{100}\sigma^2\)
bagging 0.5 4.5 + 0.045 = 4.545
random forest 0.15 1.35 + 0.0765 = 1.4265

Same number of trees, a third of the variance.

Typical random-forest choice of \(m\): classification with \(p = 9\) inputs, and regression with \(p = 12\).

\(\sqrt9 = 3\); \(12/3 = 4\).

2. Boosting

In plain words

Start with a model that predicts 0. Look at what’s still wrong (the residuals). Fit a small tree to the residuals, add a fraction \(\eta\) of it to the model, update the residuals, and repeat \(B\) times. Each tree learns a little of what the previous ones missed. Small \(\eta\) = slow, careful learning.

The algorithm (week 6 slide 30):

  1. Set \(\hat f(x) := 0\) and \(r_i := y_i\) for all \(i\).
  2. For \(b = 1, \dots, B\): fit a tree \(\hat f^b\) with \(d\) splits to \((x_i, r_i)\); update \(\hat f(x) := \hat f(x) + \eta\hat f^b(x)\); update \(r_i := r_i - \eta\hat f^b(x_i)\).
  3. Output \(\hat f(x) = \sum_b\eta\hat f^b(x)\).

At every step \(r_i = y_i - \hat f(x_i)\): the residuals really are the current errors.

Worked example 2: two rounds with stumps. \(x = (1, 2, 3, 4)\), \(y = (1, 2, 5, 6)\), \(\eta = 0.5\), \(d = 1\) (one split).

Common mistakes

  • Fitting the next tree to \(y\) instead of the current residuals.
  • Adding the whole tree. Only \(\eta\hat f^b\) is added; the residual falls by the same amount.
  • Big trees. Boosting uses small trees (\(d\) = 1 or 2 splits); bagging uses deep ones.
  • “Boosting can’t overfit.” It can: with large \(B\) it fits the noise. Choose \(B\) by validation.

\(r_i - 0.1\hat f^b(x_i)\): \(2 - 0.1 = 1.9\), \(1 - 0.2 = 0.8\), \(3 - 0.4 = 2.6\), \(5 - 0.5 = 4.5\), \(4 - 0.4 = 3.6\).

Stage test

(4 marks; 2025 Q3a.) Compare bagging and boosting: how each builds its ensemble, and which can overfit as the number of trees grows, with a reason.

Bagging draws \(B\) bootstrap samples, grows a deep tree on each independently, and averages their predictions (or takes a majority vote). Averaging reduces variance and leaves bias unchanged, so adding more trees never makes it overfit; the error simply levels off. Boosting grows small trees one after another: each is fitted to the residuals of the current model and added with a small weight \(\eta\), so the ensemble gradually reduces bias. Because every new tree fits whatever error remains, with enough trees it starts fitting noise, so boosting can overfit and \(B\) (with \(d\) and \(\eta\)) must be chosen by validation.
