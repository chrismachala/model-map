K-means and hierarchical clustering

No labels now, but the same tools. K-means is distances, means and squared error, minimised by alternating two easy steps. Hierarchical clustering turns distances between points into distances between groups. This stage runs K-means to convergence by hand, with the SSE computed from gaps to each centroid at every step, then builds a dendrogram.

1. The objective, and how to compute it correctly

In plain words

K-means wants \(K\) tight groups. “Tight” is measured by the SSE: for every point, the squared distance to its own cluster’s centre, all added up. A centre is the mean of its cluster’s points. So every term in the SSE is “point minus its centroid, squared”, never the point’s coordinates squared on their own.

\[\boxed{J_{SSE} = \sum_{j=1}^{K}\sum_{x\in\omega_j}\|x - \mu_j\|^2 = \sum_{j=1}^K\sum_{x\in\omega_j}\Big[(x_1 - \mu_{j1})^2 + (x_2 - \mu_{j2})^2\Big]}\]

Symbol Meaning
\(K\) number of clusters
\(\omega_j\) the set of points in cluster \(j\)
\(\mu_j\) cluster \(j\)’s centre (in the update step, the centroid of \(\omega_j\))
\(\|x - \mu_j\|^2\) squared distance from \(x\) to its own centre: gaps, squared, added

Worked example 1: one cluster’s SSE, the right way and the wrong way. Cluster \(\omega_2 = \{(6, 4), (8, 5), (7, 9)\}\).

Centroid: \(\mu_2 = \big(\frac{6 + 8 + 7}{3}, \frac{4 + 5 + 9}{3}\big) = (7, 6)\).

point \(x_1 - 7\) \(x_2 - 6\) squared gaps \(\|x - \mu_2\|^2\)
(6, 4) −1 −2 1 + 4 5
(8, 5) 1 −1 1 + 1 2
(7, 9) 0 3 0 + 9 9
total 0 0 16

SSE of \(\omega_2\) = 16.

The wrong way: \(6^2 + 4^2 + 8^2 + 5^2 + 7^2 + 9^2 = 271\). That adds up squared distances to the origin, which depends on where you put the axes and says nothing about how tight the cluster is. If your SSE is bigger than the squared distances between the points themselves, you’ve almost certainly squared raw coordinates.

Common mistakes in the SSE

  • Squaring raw coordinates instead of gaps to the centroid. Every row needs “minus \(\mu\)”.
  • The wrong centre. Each point uses its own cluster’s centre, not the nearest one from a different step, and not the overall mean.
  • Old vs new centres. “\(J\) after the update” uses the new centroids; “\(J\) for the current assignment and centres” uses whatever centres are current. Read the question.
  • Square roots. None: it’s squared distances.
  • Forgetting the gap columns sum to zero. If they don’t, the centroid is wrong.

Try it with me. Cluster \(\{(1, 1), (3, 1), (2, 4)\}\).

Give the centroid.

\((1 + 3 + 2)/3 = 2\) and \((1 + 1 + 4)/3 = 2\).

Give each point’s squared distance to the centroid, and the SSE.

\((1, 1)\): gaps \((-1, -1)\), \(1 + 1 = 2\). \((3, 1)\): gaps \((1, -1)\), \(2\). \((2, 4)\): gaps \((0, 2)\), \(4\). SSE \(= 8\).

2. The algorithm, run to convergence

In plain words

Start with \(K\) centres. Then repeat two steps until nothing changes: assign every point to its nearest centre; update every centre to the mean of its points. Each step can only lower \(J\), so it must stop.

  1. Assign each point to the nearest centre (A1). Lowers \(J\): each point picks its smallest term.
  2. Update each centre to the centroid of its points (A2). Lowers \(J\): the mean minimises squared distance (A3).

Worked example 2: K-means by hand. Points \(x_1 = (1, 1)\), \(x_2 = (3, 1)\), \(x_3 = (2, 4)\), \(x_4 = (6, 4)\), \(x_5 = (8, 5)\), \(x_6 = (7, 9)\). \(K = 2\), starting centres \(\mu_1 = (0, 4)\), \(\mu_2 = (4, 1)\).

Iteration 1, assign (squared distances; no roots needed to compare):

point to \(\mu_1 = (0, 4)\) to \(\mu_2 = (4, 1)\) nearest
(1, 1) 1 + 9 = 10 9 + 0 = 9 2
(3, 1) 9 + 9 = 18 1 + 0 = 1 2
(2, 4) 4 + 0 = 4 4 + 9 = 13 1
(6, 4) 36 + 0 = 36 4 + 9 = 13 2
(8, 5) 64 + 1 = 65 16 + 16 = 32 2
(7, 9) 49 + 25 = 74 9 + 64 = 73 2

\(J\) with these starting centres: \(9 + 1 + 4 + 13 + 32 + 73 = 132\).

Iteration 1, update. Cluster 1 = \(\{(2, 4)\}\), so \(\mu_1 = (2, 4)\). Cluster 2 = the other five: \(\mu_2 = \big(\frac{1 + 3 + 6 + 8 + 7}{5}, \frac{1 + 1 + 4 + 5 + 9}{5}\big) = (5, 4)\). \(J\) with the new centres: \(0 + [16 + 9] + [4 + 9] + [1 + 0] + [9 + 1] + [4 + 25] = 78\).

Iteration 2, assign:

point to \((2, 4)\) to \((5, 4)\) nearest
(1, 1) 1 + 9 = 10 16 + 9 = 25 1
(3, 1) 1 + 9 = 10 4 + 9 = 13 1
(2, 4) 0 9 1
(6, 4) 16 1 2
(8, 5) 36 + 1 = 37 9 + 1 = 10 2
(7, 9) 25 + 25 = 50 4 + 25 = 29 2

\(J = 10 + 10 + 0 + 1 + 10 + 29 = 60\).

Iteration 2, update. Cluster 1 = \(\{(1, 1), (3, 1), (2, 4)\}\), \(\mu_1 = (2, 2)\). Cluster 2 = \(\{(6, 4), (8, 5), (7, 9)\}\), \(\mu_2 = (7, 6)\). \(J = 8 + 16 = 24\) (from the try-it and worked example 1).

Iteration 3: every point stays put (check: \((6, 4)\) is \(16 + 4 = 20\) from \((2, 2)\) and \(1 + 4 = 5\) from \((7, 6)\)), so the centres don’t move. Converged, with \(J = 24\).

\(J\) went \(132 \to 78 \to 60 \to 24\): it never rose.

Common mistakes in the algorithm

  • Updating centres one point at a time. Assign all points first, then recompute all centres.
  • Comparing distances instead of squared distances is fine, but don’t mix the two in one table.
  • Ties: the slides keep the current assignment.
  • Stopping after one iteration. Run until no point changes cluster.

3. Local minima and choosing \(K\)

K-means always stops (finitely many assignments, \(J\) never rises), but where it stops depends on the start: it can get stuck in a local minimum. The cure: several random starts, keep the lowest \(J\). And \(J\) always falls as \(K\) grows (\(K = n\) gives \(J = 0\)), so \(K\) can’t be chosen by \(J\) alone: use an elbow plot or the purpose of the clustering.

You run K-means twice on the same data with \(K = 3\) and get \(J = 41\) and \(J = 57\). What should you conclude?

K-means’ result depends on its starting centres.

4. Hierarchical clustering: distances between groups

In plain words

Start with every point alone. Repeatedly merge the two closest clusters until one is left. “Closest” for groups needs a rule (the linkage), built from point distances. The merge heights draw the dendrogram; cut it at a height to get clusters.

Linkage Distance between clusters \(A\) and \(B\)
single smallest point-to-point distance
complete largest point-to-point distance
average mean of all point-to-point distances
centroid distance between the two centroids

Worked example 3: the four linkages. \(A = \{(0, 0), (2, 0)\}\), \(B = \{(5, 4), (6, 0)\}\).

from \(A\) to \(B\) distance
(0, 0) (5, 4) \(\sqrt{25 + 16} = \sqrt{41} = 6.403\)
(0, 0) (6, 0) 6
(2, 0) (5, 4) \(\sqrt{9 + 16} = 5\)
(2, 0) (6, 0) 4

Single \(= 4\). Complete \(= 6.403\). Average \(= (6.403 + 6 + 5 + 4)/4 = 5.351\). Centroid: \(\bar a = (1, 0)\), \(\bar b = (5.5, 2)\), distance \(\sqrt{4.5^2 + 2^2} = \sqrt{24.25} = 4.924\).

Worked example 4: a dendrogram in 1D. Points \(1, 2, 5, 9, 11\).

step single linkage merges height complete linkage merges height
1 {1} + {2} 1 {1} + {2} 1
2 {9} + {11} 2 {9} + {11} 2
3 {1, 2} + {5} 3 (5 − 2) {1, 2} + {5} 4 (5 − 1)
4 {1, 2, 5} + {9, 11} 4 (9 − 5) {1, 2, 5} + {9, 11} 10 (11 − 1)

Cutting the complete-linkage dendrogram at height 5 gives two clusters, \(\{1, 2, 5\}\) and \(\{9, 11\}\).

Common mistakes

  • “Average linkage” = distance between the averages. That’s centroid linkage. Average linkage averages the distances.
  • Recomputing from scratch after each merge is fine, but use the merged cluster’s points, not its centre (except for centroid linkage).
  • Single linkage chains; centroid linkage can produce inversions (a later merge at a lower height).

Stage test

(4 marks; 2023 Q5.) Describe the K-means algorithm and explain why it always terminates. Does it always find the best clustering?

K-means seeks \(K\) clusters minimising \(J = \sum_{j=1}^K\sum_{x\in\omega_j}\|x - \mu_j\|^2\). Starting from \(K\) initial centres, it repeats two steps: assign each point to its nearest centre, then replace each centre by the mean of the points assigned to it. The assignment step cannot increase \(J\) (each point moves to its closest centre) and the update step cannot increase \(J\) (the mean minimises the sum of squared distances). Since \(J\) never increases and there are only finitely many ways to partition the data, the algorithm must stop. It converges to a local minimum that depends on the initial centres, so in practice it is run from several random starts and the solution with the smallest \(J\) is kept.
