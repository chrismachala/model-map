Random forests and boosting

Two ways to improve on bagging. Random forests make the trees disagree by letting each split choose from only m random attributes. Boosting grows small trees one after another, each fitted to what the model still gets wrong, adding only a fraction η of each.

Book: what to read for this stage

ISLP 8.2.2 Random forests (p346–347) and 8.2.3 Boosting (p347–350, Algorithm 8.2): read. 8.2.4 BART: skip. 8.2.5 summary: skim.

1. Random forests

Bagged trees are correlated: if one attribute is strong, nearly every tree splits on it first, and averaging near-copies barely helps. A random forest is bagging plus one rule: at every split, choose a fresh random subset of \(m\) of the \(p\) attributes and split on the best of those.

Typical \(m\): \(\sqrt p\) (classification), \(p/3\) (regression). \(m = p\) is bagging.

Why it helps: \(B\) trees with variance \(\sigma^2\) and correlation \(\rho\) average to variance \(\rho\sigma^2 + \frac{1 - \rho}{B}\sigma^2\). More trees kill only the second term; lowering \(\rho\) shrinks the first.

Trees have variance \(\sigma^2 = 4\) and pairwise correlation \(\rho = 0.5\). What is the variance of the average of \(B = 100\) trees?

\(0.5 \times 4 + \frac{0.5}{100} \times 4 = 2 + 0.02 = 2.02\). Even infinitely many trees can’t go below 2.

2. Boosting (Algorithm 8.2)

  1. \(\hat f := 0\), \(r_i := y_i\).
  2. For \(b = 1, \dots, B\): fit a tree \(\hat f^b\) with \(d\) splits to \((x_i, r_i)\); \(\hat f := \hat f + \eta\hat f^b\); \(r_i := r_i - \eta\hat f^b(x_i)\).
  3. Output \(\hat f = \sum_b\eta\hat f^b\).

Slide 33. Residuals \((2, 1, 3, 5, 4)\), new tree predicts \((1, 2, 4, 5, 4)\). \(\eta = 0.1\): \((1.9, 0.8, 2.6, 4.5, 3.6)\). \(\eta = 1\): \((1, -1, -1, 0, 0)\): greedy.

A residual is 3, the new tree predicts 6 there, and \(\eta = 0.1\). What is the new residual?

\(3 - 0.1 \times 6 = 2.4\).

role too big
\(B\) number of trees overfits (slowly): choose by validation
\(\eta\) learning rate (0.01, 0.001) greedy; smaller \(\eta\) needs larger \(B\)
\(d\) splits per tree (often 1: stumps) each tree overfits

Stage test

(4 marks; 2025 Q3a.) Can bagging and boosting overfit if the number of trees is too large? Justify both answers.

Bagging: no. Its trees are grown independently on bootstrap samples and averaged; adding trees leaves the bias unchanged and only makes the average more precise, so the test error levels off. Boosting: yes. Each tree is fitted to the current training residuals, so with enough trees the model fits the training data ever more closely, eventually the noise, and the test error rises again (slowly when \(\eta\) is small); \(B\) must be chosen by validation or cross-validation.

A classification problem has \(p = 16\) attributes. What is the usual choice of \(m\) for a random forest?

\(\sqrt{16} = 4\).

A random forest with \(m = p\) is…

Every attribute is a candidate at every split: ordinary tree growing on bootstrap samples.

Tick every true statement.

Forests: deep, decorrelated, averaged. Boosting: small, sequential, summed with weight \(\eta\).
