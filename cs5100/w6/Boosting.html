Boosting

Instead of many independent deep trees, grow small trees one after another. Each new tree is fitted to what the model still gets wrong (the residuals), and only a small fraction η of it is added. Slow learning that generalises well, but too many trees can overfit.

Question type: ensemble; on the slides, regression only.
Week: 6 (slides 28–39).
Book: ISLP 8.2.3 (p347–350), Algorithm 8.2.
Past paper: 2025 Q3(a) (can bagging / boosting overfit?).
Techniques on this page: the boosting algorithm, residual updates by hand, the three tuning parameters, boosting vs bagging.

The problem it solves

Bagging reduces variance but can’t reduce bias. Boosting attacks the errors directly: start from nothing, and repeatedly add a little bit of a small tree that predicts the current errors. Each step improves the model where it’s worst. Because each tree only nudges the model, it doesn’t chase the data as hard as one big tree would.

Words you’ll hear

Word Plain meaning
residual \(r_i\) current error \(y_i - \hat f(x_i)\)
learning rate / shrinkage \(\eta\) the fraction of each new tree added (0.01, 0.001)
\(d\) number of splits per tree (\(d + 1\) leaves)
stump a tree with one split (\(d = 1\))
sequential each tree depends on the trees before it

Technique 1: the algorithm (slide 30)

  1. \(\hat f(x) := 0\), \(r_i := y_i\).
  2. For \(b = 1..B\): fit a tree \(\hat f^b\) with \(d\) splits to \((x_i, r_i)\); \(\hat f(x) := \hat f(x) + \eta\hat f^b(x)\); \(r_i := r_i - \eta\hat f^b(x_i)\).
  3. Output \(\hat f(x) = \sum_b\eta\hat f^b(x)\).

At every step \(r_i = y_i - \hat f(x_i)\), which is why they’re called residuals (slide 31).

Slide 33 toy example. Residuals \((2, 1, 3, 5, 4)\), new tree predicts \((1, 2, 4, 5, 4)\). \(\eta = 0.1\): new residuals \((1.9, 0.8, 2.6, 4.5, 3.6)\): everything shrinks a little. \(\eta = 1\): \((1, -1, -1, 0, 0)\): two points fitted perfectly in one go, three overshoot. Fast, greedy, overfits sooner.

Technique 2: the three parameters (slide 34)

role typical too big
\(B\) number of rounds choose by validation / CV overfits (slowly)
\(\eta\) how fast it learns 0.01, 0.001 greedy; smaller \(\eta\) needs bigger \(B\)
\(d\) size of each tree = interaction order often 1 (stumps: additive model) trees overfit

Technique 3: boosting vs bagging (and the 2025 question)

bagging / random forest boosting
trees built independently, on bootstrap samples sequentially, on residuals
tree size deep small (stumps)
reduces variance bias (slowly)
combine equal average / vote sum of \(\eta\hat f^b\)
more trees can’t overfit can overfit

2025 Q3(a) model answer. Bagging: no; more trees leave the bias unchanged and only reduce the variance of the average. Boosting: yes; each tree fits the training residuals more closely, so eventually the trees fit the noise, and \(B\) must be chosen by validation.

Gene-expression slides (36–38): the random-forest figure is 15-class and the boosting figure is 2-class, so their error rates can’t be compared with each other (slide 38).
