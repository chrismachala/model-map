Comparing two algorithms

Algorithm 1 makes 13.4% errors, Algorithm 0 makes 16.8%. Real difference or luck? Throw away the cases where they agree, treat each disagreement as a coin flip, and ask how surprising the score would be if neither were better.

Question type: not a model: a hypothesis test for “is classifier 1 better than classifier 0?”.
Week: 5 (slides 26–35).
Book: ISLP 13.1 (p558–563) for null hypotheses, p-values and Type I/II errors. The slides’ binomial sign test isn’t in ISLP; this page covers it.
Techniques on this page: contingency table, null hypothesis, binomial probabilities, the one-sided p-value, significance levels.

The problem it solves

A test set is a random sample. Two classifiers with exactly the same true error rate will still score differently on any particular 238 test cases. Before claiming “mine is better” you need to know whether the gap is bigger than luck would usually produce. A hypothesis test answers that with a single number, the p-value.

Words you’ll hear

Word Plain meaning
contingency table 2 × 2 counts: both right, only 0 right, only 1 right, both wrong
null hypothesis \(H_0\) the boring explanation you try to rule out: “1 is not better than 0”
binomial distribution number of heads in \(N\) independent coin flips
p-value probability of a result at least this extreme if \(H_0\) were true
significance level \(\epsilon\) the cut-off (5% or 1%) fixed in advance
Type I error rejecting a true \(H_0\) (false alarm), probability ≤ \(\epsilon\)
sign test / McNemar names for this test on paired right/wrong data (not used on the slides)

Technique 1: keep only the disagreements

Alg 1 correct Alg 1 wrong
Alg 0 correct 189 9
Alg 0 wrong 17 23

Error rates: Alg 0 \((17 + 23)/238 = 16.8\%\), Alg 1 \((9 + 23)/238 = 13.4\%\). The 189 + 23 agreements say nothing about which is better: drop them. Left: \(N = 26\) disagreements, of which Alg 1 wins \(k = 17\).

Technique 2: the binomial p-value

If \(H_0\) holds, each disagreement is a fair coin (\(p = \frac12\); if Alg 1 were worse, \(p < \frac12\) and 17 wins would be even rarer). So

\[p\text{-value} = P(Y \ge k) = \sum_{j=k}^{N}\binom{N}{j}\frac{1}{2^N}, \qquad \binom Nj = \frac{N!}{j!(N-j)!}.\]

For 17 of 26: \(p = 1 - F(16) \approx 0.0843\); in Python 1 - scipy.stats.binom.cdf(16, 26, 1/2).

Decision: reject \(H_0\) iff \(p \le \epsilon\). Here \(0.084 > 0.05\): can’t reject. The data don’t show Algorithm 1 is better.

By hand. \(N = 10\) disagreements, Algorithm 1 wins \(k = 9\). \(p = \frac{\binom{10}{9} + \binom{10}{10}}{2^{10}} = \frac{11}{1024} = 0.0107\). Reject at 5%, not at 1%.

Technique 3: reading the result correctly

  • “Fail to reject” ≠ “they’re equal”. It means not enough evidence.
  • The p-value is \(P(\text{data} \mid H_0)\), not \(P(H_0 \mid \text{data})\).
  • Same proportions, more data: smaller p-value (34 of 52 gives 0.018).
  • One-sided (is 1 better?) as on the slides; for “different?” double it.
  • Small p-value = probably real, not necessarily large or useful.

Slide 29 typo: “Algorithm 1 to beat Algorithm 2” means Algorithm 0. Exam note: the 2024 paper had a 23-mark question on multiple testing (Bonferroni and Holm, ISLP 13.3). It isn’t on this year’s week 5 slides; ask whether it’s examinable. A worked version is in exam-prep/CS5100_Past_Paper_Patterns.md.
