Resampling and averaging many models

Two ideas about data you don't have. First: hold some data back so you can measure test error honestly (train / validation / test). Second: fake new training sets by resampling the one you have (the bootstrap), fit a model to each, and average. Averaging cuts variance, by a formula you can compute.

1. Train, validation, test

Training error always falls as flexibility grows, so it can’t choose \(K\), \(\lambda\), \(\alpha\) or the degree. Split the data:

  • Training set: fit the parameters (\(\beta\), the tree, the weights).
  • Validation set: choose the knob (Toolkit 5) by comparing validation error.
  • Test set: touch once, at the end, to report the error of the final choice.

Using the test set to choose the knob makes the reported error optimistic. That’s the 2023 Q1 short answer.

You try 20 values of \(\lambda\) for ridge and report the lowest test error among them as your model’s performance. What’s wrong?

Picking the minimum of 20 noisy numbers favours the one that got lucky on those particular test points.

2. The bootstrap

A bootstrap sample is \(n\) draws with replacement from the \(n\) training points. Some points appear several times; others not at all. From Toolkit 6, each point is left out with probability

\[\Big(1 - \frac1n\Big)^n \to e^{-1} \approx 0.368,\]

so each bootstrap sample contains about 63.2% of the distinct points, and about 36.8% are out of bag (OOB).

Worked example. \(n = 4\): \((3/4)^4 = 0.316\). \(n = 10\): \((0.9)^{10} = 0.349\). \(n = 1000\): \(0.368\).

3. Averaging cuts variance

If \(B\) models each have prediction variance \(\sigma^2\) and every pair has correlation \(\rho\), their average has variance

\[\boxed{\mathrm{Var}\Big(\frac1B\sum_{b=1}^{B}\hat f_b\Big) = \rho\sigma^2 + \frac{1 - \rho}{B}\sigma^2}\]

  • Independent models (\(\rho = 0\)): \(\sigma^2/B\), which goes to 0.
  • Correlated models: as \(B \to \infty\) it only falls to \(\rho\sigma^2\). More trees can’t beat that floor.
  • Bias is unchanged by averaging: the average of \(B\) similar models is aimed at the same place.

This is the whole logic of week 6. Bagging = bootstrap + deep (low-bias, high-variance) trees + average. Random forests = bagging + a random subset of \(m\) inputs at every split, which makes the trees less alike, lowering \(\rho\) and so the floor.

4. Out-of-bag error: a free validation set

Each point is OOB for about a third of the trees. Predict it using only those trees (average or vote, Toolkit 2), compare with its true label, and average over all points: that’s the OOB error, an honest estimate of test error with no data held back. It is the most repeated exam calculation in the second half (2023 Q4 and 2025 Q3).

Worked example. Three bootstrap samples from points \(\{1, 2, 3, 4\}\): \(S_1 = \{1, 1, 2, 3\}\), \(S_2 = \{2, 3, 3, 4\}\), \(S_3 = \{1, 2, 4, 4\}\). Point 4 is OOB for \(S_1\) only, so it’s predicted by tree 1 alone. Point 1 is OOB for \(S_2\) only; point 3 for \(S_3\) only; point 2 is in every sample, so it has no OOB prediction and is left out of the OOB error.

5. Boosting: sum, not average

Boosting (w6) also combines \(B\) trees, but in sequence: each small tree is fitted to the current residuals (Toolkit 3) and added in with shrinkage \(\eta\) (Toolkit 5): \(\hat f(x) = \sum_b\eta\hat f_b(x)\). It reduces bias, not just variance, and that’s why too many trees can overfit while bagging can’t.
