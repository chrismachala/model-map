Density estimation and semi-supervised learning

The last week's non-parametric density estimates are "count the nearby points" again. The histogram and Parzen window use an indicator, the smooth kernel uses a Gaussian bump, and the bandwidth is one more flexibility knob. Semi-supervised K-means reuses K-means with a few labels.

Built from

A2 counting with indicators: \(k/(nV)\) · A7 the Gaussian kernel · A1 the kernel’s distance \((x - x_i)/h\) · A5 bandwidth \(h\) as the bias-variance dial · K-means from Model 9. Full pages: density estimation, semi-supervised learning; week-order stage: 25.

1. The assembly

From \(P \approx k/n\) and \(P \approx f(x)V\) (week 7 slides):

\[f(x) \approx \frac{k}{nV}\quad\Longrightarrow\quad f(x) = \frac{1}{nh^p}\sum_{i=1}^{n}K\Big(\frac{x - x_i}{h}\Big)\]

  • Parzen window: \(K(u) = 1\) if \(\lvert u_j\rvert \le \frac12\) for all \(j\), else 0. It’s an indicator (A2): \(\sum_iK(\cdot)\) counts the points in the cube of side \(h\) around \(x\), so this is exactly \(k/(nV)\) with \(V = h^p\).
  • Gaussian kernel: \(K(u) = (2\pi)^{-p/2}e^{-\frac12u^Tu}\) (A7): every point contributes, nearer points more. Smooth instead of blocky.
  • Bandwidth \(h\) (A5): large \(h\) over-smooths (bias); small \(h\) is spiky (variance).

Worked example (week 7 slides). \(n = 10\), \(h = 4\), \(p = 1\): \(f(10) = \frac{1}{10 \times 4}\times(\text{number of } x_i \text{ within } 2 \text{ of } 10) = \frac{1}{40}\times1 = 0.025\).

2. Semi-supervised K-means

A few labelled points, many unlabelled. Seeded K-means uses the labelled points’ means as the starting centres (A2), then runs ordinary K-means. Constrained K-means does the same but never reassigns the labelled points. Both are Model 9 with a better start.

In kernel density estimation, what happens as the bandwidth \(h \to 0\)?

Each bump shrinks around its own point. Large \(h\) gives the opposite: one broad smear that hides the structure.

Stage test

\(n = 20\) points in one dimension. A region of width \(V = 2\) around \(x\) contains \(k = 2\) of them. Estimate \(f(x)\) by \(k/(nV)\).

\(2/(20 \times 2) = 0.05\).

Why is the Parzen-window estimate an example of “count the points near \(x\)” (Toolkit 2)?

The Gaussian kernel replaces the hard count with a distance-weighted one.
