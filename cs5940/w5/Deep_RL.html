Deep reinforcement learning

Q-learning keeps one number per (state, action). That's fine for a 3-cell corridor and hopeless for a screen of pixels. Deep RL swaps the table for a neural network that estimates Q, or picks actions directly, so that what it learns in one situation carries over to similar ones.

Kind: learning agent (deep, mostly model-free, reinforcement learning).
Week: 5, Part A (slides 5 to 26).
Book: not in Wooldridge. Optional: Mnih et al. 2015 (DQN, Nature), Sutton and Barto ch. 9 and 13.
Techniques on this page: the neuron and backpropagation (recap), function approximation, DQN and its learning target, experience replay and target networks, value-based vs policy-based vs actor–critic, model-free vs model-based (AlphaZero), failure modes.

The problem it solves

In week 4 the agent learned \(Q(s, a)\) as a table (slide 9). Two things break when \(s\) is a camera image:

  1. Size. Every different image is a different state. The table would need more rows than there are atoms.
  2. No reuse. A table learns nothing about a state it has never visited, even if it differs from a familiar one by one pixel (the ball moved slightly).

The fix: replace the lookup with an approximation, \(Q(s, a) \to Q_\theta(s, a)\), where \(\theta\) are the weights of a neural network (slide 11). Changing \(\theta\) changes the estimates for many states at once, including ones never seen. That’s generalisation, and it’s also why training gets unstable.

The framing question for the whole of topic 5: how do neural networks learn from data and experience, and how can what they learn support an agent’s decisions?

Words you’ll hear

Word or symbol Plain meaning
neuron weighted sum of inputs plus a bias, passed through an activation: \(y = \phi(w \cdot x + b)\)
backpropagation working out how much each weight contributed to the loss (its gradient)
optimiser the rule that nudges the weights downhill on the loss (e.g. gradient descent)
deep several learned layers stacked; each builds more useful features from the last
\(Q_\theta(s, a)\) a network with weights \(\theta\) that outputs one Q-value per action
DQN Deep Q-Network (Mnih et al. 2015): Q-learning with a network, from Atari pixels
target network \(Q_{\theta^-}\) a frozen copy of the network used only to compute targets; refreshed now and then

policy \(\pi_\theta(a \mid s)\) a network that outputs action probabilities directly
actor–critic actor = policy network that acts; critic = value network that helps train it
model-free / model-based learn values or a policy directly / use known or learned dynamics to plan

Technique 1: the neural network recap

Problem it solves: a flexible function you can fit to data by adjusting numbers.

A neuron combines inputs: \(z = w_1x_1 + w_2x_2 + w_3x_3 + b\), then \(y = \phi(z)\) (slide 5). The weights set each input’s influence, the bias shifts the response, and the activation \(\phi\) (often non-linear) transforms the score.

Training loop (slide 6): forward pass to get a prediction \(\hat y\) → loss compares \(\hat y\) with the target \(y\) → backpropagate to get each weight’s gradient → update the weights to reduce the error. Repeat over many examples.

Deep means several hidden layers (slide 7). Early layers find simple features, later ones combine them.

Worked example. Weights \(w = (0.5, -1, 2)\), bias \(b = 0.5\), input \(x = (2, 1, 0.5)\), ReLU activation. \(z = 1 - 1 + 1 + 0.5 = 1.5\), so \(y = \max(0, 1.5) = 1.5\). With \(x = (0, 2, 0)\): \(z = -2 + 0.5 = -1.5\), \(y = 0\).

Technique 2: function approximation

Problem it solves: huge state spaces, and generalising to states never seen.

Swap the table for \(Q_\theta(s, a)\) (slide 11): observation (pixels) → network → one output per action. Earlier layers learn a representation of the observation; later layers turn it into values.

Generalisation is not correctness (slide 11 caveat). The network gives an estimate for a new state; nothing guarantees it’s right. A table at least knows when it knows nothing.

Technique 3: DQN and its learning target

Problem it solves: Q-learning from raw pixels, with no model of the game.

DQN (slide 12) takes four recent frames, outputs \(Q_\theta(s_t, \cdot)\) for every action, picks one ε-greedily, and learns from the game score alone. No game physics is given.

Why four frames? One frame can’t show which way the ball is moving (slide 13): same pixels, different underlying state. That’s partial observability from week 4. A short history helps; it doesn’t always remove the problem.

What it learns from one transition (slide 14):

\[y_t = \begin{cases} r_{t+1} & \text{if the episode ends} \\ r_{t+1} + \gamma \max_{a'} Q_{\theta^-}(s_{t+1}, a') & \text{otherwise}\end{cases}\]

\[L(\theta) \approx \frac{1}{N}\sum_{i=1}^{N}\big(y_i - Q_\theta(s_i, a_i)\big)^2\]

Same target as tabular Q-learning (“reward now + value later”), but instead of nudging one table cell, gradient descent nudges \(\theta\) to shrink the squared gap between target and prediction, averaged over a mini-batch.

Worked example. \(\gamma = 0.9\). A replayed transition has \(r = 1\), and the target network says \(Q_{\theta^-}(s', \cdot) = (2, 5, 3)\). Target \(y = 1 + 0.9 \times 5 = 5.5\). The online network currently predicts \(Q_\theta(s, a) = 4\), so this sample’s squared error is \((5.5 - 4)^2 = 2.25\), and training pushes \(Q_\theta(s, a)\) up. If the transition ended the episode, \(y = 1\) and the error is \((1 - 4)^2 = 9\).

Technique 4: experience replay and the target network

Problem it solves: deep Q-learning is unstable to train (slide 15).

Problem Why it hurts Fix
Correlated samples consecutive frames are nearly identical, so training on them in order is like studying one page 100 times experience replay: store transitions in a buffer and train on random mini-batches
Moving targets the same weights make the prediction and the target, so every update moves the goalposts target network \(Q_{\theta^-}\): a frozen copy for targets, copied from \(\theta\) every so often

Replay also lets one experience be reused for several updates (slide 16). It stores real past transitions, not a learned simulator, so old data can go stale if the game changes.

Poll 1 (slide 17). The target network exists to stop the targets shifting every time θ changes (B). Not (A): de-correlating frames is replay’s job. Not (C): it is not a model of the game. Not (D): neither trick guarantees convergence; they improve stability.

Technique 5: value-based, policy-based and actor–critic

Problem it solves: different action spaces suit different things to learn (slides 19 to 20).

Value-based (DQN) Policy-based (policy gradient)
learns \(Q_\theta(s, a)\) \(\pi_\theta(a \mid s)\)
outputs expected return for each action action probabilities, or a continuous action distribution
acts by \(\arg\max_a Q_\theta(s, a)\) (ε-greedy in training) sampling \(a \sim \pi_\theta(\cdot \mid s)\)
good for small discrete action sets stochastic policies, continuous control (steering angle, joint torque)

Both can be model-free.

Actor–critic splits the work: the actor \(\pi_\theta\) chooses actions; the critic \(V_w(s)\) estimates values that help train the actor. The critic is a training aid: at deployment the actor can act alone. PPO combines policy optimisation with value estimation (details out of scope). You’ll meet parameterised policies again in LLM post-training.

Technique 6: model-free vs model-based (AlphaGo and AlphaZero)

Problem it solves: learning alone vs learning plus look-ahead (slides 21 to 22).

Model-free Model-based
learn a policy or value directly from experience; no transition model used to choose actions use known or learned dynamics to predict futures and plan
\(a = \arg\max_{a'} Q_\theta(s, a')\) \(a = \text{Plan}(s; T \text{ or } \hat T)\)
DQN AlphaZero (model given: the rules of Go), MuZero (model learned)

AlphaGo / AlphaZero = learning + search. A learned policy suggests promising moves, a learned value scores positions (one network in AlphaZero), and MCTS looks ahead using the known rules, consulting those predictions. AlphaGo (2016) used human expert games + self-play RL + search; AlphaZero (2018) used self-play only, no human games.

Hide and seek (slide 23): self-play produced strategies and counter-strategies with boxes and ramps that nobody scripted. When the other agents are learning too, your environment keeps changing, so it’s no longer a single-agent MDP with a fixed transition law (the slide 24 discussion). That’s a bridge to week 7.

Technique 7: how deep RL fails

Problem it solves: knowing what not to claim (slide 25).

  • Sample efficiency: may need millions of interactions.
  • Instability: function approximation + bootstrapping + off-policy learning can interact badly (the “deadly triad”; the slides list the three).
  • Reward misspecification: high reward ≠ the behaviour you wanted (week 4’s boat race).
  • Generalisation: success in training environments needn’t survive new ones.
  • Model error (model-based): planning with wrong learned dynamics compounds errors.

The slide ends with the question that sets up Part B: could we first learn broad representations from huge amounts of data, then optimise behaviour for particular tasks? That’s what LLMs do.
