How an LLM generates text

An LLM does one thing: given the tokens so far, it gives a probability for every possible next token. Pick one, append it, repeat. Everything else on this page (tokens, attention, softmax, temperature, pretraining) is a detail of how that one step works and how the model learned it.

Kind: toolkit (what’s inside the model an LLM agent is built on).
Week: 5, Part B, first half (slides 27 to 41).
Book: not in Wooldridge. Optional: Raschka, Build a Large Language Model (From Scratch) ch. 1 to 3; the Transformer Explainer (linked on slide 55).
Techniques on this page: next-token prediction and the chain rule, Shannon’s k-gram models, tokens, self-attention and the causal mask, logits and softmax, temperature and decoding, pretraining with cross-entropy.

The problem it solves

Deep RL learns from reward: act, get a score, change the weights to get more. LLM pretraining learns from a completely different signal (slide 27): take real text, hide the next token, and change the weights so the model predicts it better. The training text supplies the answers, so no acting and no reward: next-token pretraining is not RL. (RL comes back later, in post-training.)

Why care in an agents module? Because the next weeks build agents around this model. You need to know exactly what it does and doesn’t do: it outputs probabilities over tokens, with fixed weights at inference, and generating text is not the same as acting in the world.

Technique 1: next-token prediction

Problem it solves: turns “generate text” into a sequence of small prediction problems.

An autoregressive model gives \(P_\theta(x_t \mid x_1, \dots, x_{t-1})\) (slide 31). The probability of a whole sequence is the product of the steps (the chain rule):

\[P_\theta(x_{1:n}) = \prod_{t=1}^{n} P_\theta(x_t \mid x_{<t})\]

To generate, apply a decoding rule (greedy or sampling) to pick a token, append it, and predict again.

Worked example. \(P(\text{The}) = 0.5\), \(P(\text{cat} \mid \text{The}) = 0.2\), \(P(\text{sat} \mid \text{The cat}) = 0.4\). Then \(P(\text{The cat sat}) = 0.5 \times 0.2 \times 0.4 = 0.04\).

Shannon got there first (1948, slides 28 to 30). He generated English with \(k\)-gram models: count which character follows each \(k\)-character context in a corpus and turn the counts into probabilities. Zero-order (uniform letters) gives XFOML RXKHRJFFJUJ; each higher order looks more like English, with no grammar rules supplied. Modern LLMs keep the same loop (predict, sample, append) but replace the count table with learned neural representations and much longer context. They are not \(k\)-gram tables.

Technique 2: tokens

Problem it solves: gives the network a fixed vocabulary of discrete IDs.

A tokenizer splits text into tokens and maps each to an ID (slide 32): “The autonomous agents cooperate.” might become The | auton | omous | agents | cooperate | .. Boundaries depend on the tokenizer. The model sees IDs and embedding vectors, never words as symbols. (That’s why costs and limits are counted in tokens, as in the practicals.)

Technique 3: self-attention and the causal mask

Problem it solves: the same token means different things in different contexts.

The embedding for “it” on its own can’t say what “it” refers to. Self-attention lets each token’s representation take in information from other tokens (slide 34): in “The robot moved the box because it was heavy”, “it” should attend strongly to “box”. Multiple heads can track different relationships at once.

Causal attention (slide 35): at position \(t\) the prediction may depend only on \(x_1, \dots, x_t\). A mask blocks every later position, so in training the model can’t peek at the token it’s supposed to predict. At inference, the model appends each new token and predicts again.

The mask as a grid. Rows = query position, columns = key position. Position 3 may look at 1, 2 and 3 only. In a 5-token sequence the allowed (query, key) pairs form a lower triangle: \(1 + 2 + 3 + 4 + 5 = 15\) of the 25 cells.

Technique 4: logits, softmax and temperature

Problem it solves: turns raw scores into a distribution you can choose from.

The last layer outputs one logit \(z_i\) per vocabulary token. Softmax (slide 36):

\[P_\theta(x_t = i \mid x_{<t}) = \frac{\exp(z_i)}{\sum_j \exp(z_j)}\]

Temperature (slide 37) divides the logits first:

\[P_T(i) = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}, \quad T > 0\]

  • \(T < 1\) concentrates probability on the likely tokens (less varied output when sampling).
  • \(T > 1\) flattens the distribution (more varied, more mistakes).
  • Greedy decoding ignores temperature: dividing every logit by the same positive \(T\) doesn’t change which one is largest.

Slide 37’s table. At \(T = 1\): The 0.50, A 0.30, One 0.15, Some 0.05. A shortcut: \(P_T(i) \propto P_1(i)^{1/T}\).

  • \(T = 0.5\): square them: 0.25, 0.09, 0.0225, 0.0025; total 0.365; divide: 0.685, 0.247, 0.062, 0.007.
  • \(T = 2\): square-root them: 0.707, 0.548, 0.387, 0.224; total 1.866; divide: 0.379, 0.294, 0.208, 0.120.

“The” is top in every column.

Poll 2 (slide 38). Greedy decoding, temperature raised from 1 to 2: nothing changes (C), the top-ranked token is the same. Temperature only matters when you sample. And it never updates the weights.

Token probabilities are not truth. A probability of 0.9 for the next token says nothing about whether the whole answer is correct (slide 36).

Technique 5: pretraining

Problem it solves: gets general language, knowledge and coding skill without hand-made labels.

Collect huge amounts of text and code. For each position, reveal the prefix and score the true next token (slide 40):

\[L_{\text{pretrain}}(\theta) = -\sum_t \log P_\theta(x_t \mid x_{<t})\]

“How surprised the model was by each true next token, added up.” Minimise it by gradient descent over many examples.

Worked example. The true next tokens got probabilities 0.5, 0.25 and 0.8. Loss \(= -(\ln 0.5 + \ln 0.25 + \ln 0.8) = 0.693 + 1.386 + 0.223 = 2.30\). A perfect model (probability 1 each time) has loss 0.

Pretraining can give (slide 41) It does not guarantee
rich reusable token representations that every output is true
general language and code generation understanding what the user meant
patterns useful for answering and solving tasks reliable reasoning or verification
transfer to prompts unlike any training example permission to act in external systems
