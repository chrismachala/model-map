The agent loop, the harness, tools and skills

Week 6 first half, around the airline clerk: workflow or agent, what the harness does at each step, where a rule like "do not book" should live, how tool calls work, and tools vs skills.

Full notes: LLM agents: the loop and the harness and Tools and skills.

1. Workflow or agent?

The deciding question is control: does the model’s output choose the next step? A program with fixed steps is a workflow, even if it calls an LLM, uses tools or retrieval. An agent picks its next step from what it just observed (and the runtime still validates and limits it).

A documentation chatbot runs exactly one search of the manual for every question, then makes one LLM call to answer. How should it be classed?

Slide 9, system B. Retrieval doesn’t make it an agent; the model never chooses the next step.

2. What the harness does

\(c_t = \text{BuildContext}(m_t, g, T, K_t)\); \(u_t \sim p_\theta(\cdot \mid c_t)\); \(a_t = \text{InterpretAndValidate}(u_t)\); \(o_{t+1} = \text{Execute}(a_t)\); \(m_{t+1} = \text{UpdateState}(\dots)\). Only \(p_\theta\) is learned.

Output types: final answer → stop; question → ask the user and wait; tool request → validate (known? valid args? permitted?) → execute, or reject. Errors and rejections are observations, fed back into the context. The runtime owns validation, permissions, limits and termination.

The model requests search_flights(date="18/04") but the tool requires YYYY-MM-DD. What should a well-built harness do?

Errors are observations. Run 2 of the autopsy also shows the harness should notice repeated identical failures.

3. Where should “do not book” live?

System prompt, skill, tool description: all advisory (the model must read and obey). Harness (a validation rule, or simply not exposing book_flight): enforced regardless of what the model generates.

A model knows a tool only from its description in the context, so tool names and descriptions are prompt engineering. A safe write tool binds to a checked quote (quote_id), needs an approval_token, and an idempotency_key so a retry never books twice.

Which placement of the rule “never book without approval” gives the strongest guarantee?

Only the harness can enforce it whatever the model writes.

4. Tools vs skills

Tool Skill
execute an operation or get data reusable know-how and procedures
named interface + schema folder with SKILL.md, optional scripts/references
model requests, harness executes harness discovers and loads on demand

Progressive disclosure: only name + description in context (≈100 tokens) → load SKILL.md when relevant → open references or run scripts only if needed. Skills are procedural memory outside the weights. MCP = a standard way to expose tools to any compatible client.

An agent has 40 skills available but only their names and one-line descriptions are in its context; it reads a skill’s full instructions only when a task needs it. What is this called?

Discover, load, use: progressive disclosure keeps many skills available while few occupy the context.
