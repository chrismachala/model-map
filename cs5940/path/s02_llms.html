LLM foundations and post-training

Week 5 Part B: what the model computes (next-token probabilities), how temperature and decoding work, what pretraining and post-training each do, and the favourite trap: which of these actually changes the weights?

Full notes: How an LLM generates text and Post-training and the three knobs.

1. Next-token prediction is not RL

An autoregressive LM gives \(P_\theta(x_t \mid x_{<t})\); a sequence’s probability is the product \(\prod_t P_\theta(x_t \mid x_{<t})\). Pretraining minimises \(-\sum_t \log P_\theta(x_t \mid x_{<t})\) on real text. The text supplies the targets, the model doesn’t act or receive reward: pretraining is not reinforcement learning. RL appears later, in some post-training.

Self-attention lets tokens use context (“it” → “box”); the causal mask stops position \(t\) seeing later tokens during training.

\(P(\text{The}) = 0.5\), \(P(\text{cat} \mid \text{The}) = 0.2\), \(P(\text{sat} \mid \text{The cat}) = 0.4\). What probability does the model give the sequence “The cat sat”?

Chain rule: \(0.5 \times 0.2 \times 0.4 = 0.04\).

2. Softmax, temperature, decoding

\(P_T(i) = \dfrac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}\). Low \(T\) sharpens, high \(T\) flattens. Shortcut: \(P_T(i) \propto P_1(i)^{1/T}\). Greedy decoding always picks the top token, and dividing all logits by the same \(T > 0\) never changes which is top.

At \(T = 1\) a model gives two tokens probabilities 0.667 and 0.333 (logits differ by \(\ln 2\)). What is the first token’s probability at \(T = 0.5\)? (Two decimal places is fine.)

Square and renormalise: \(0.667^2 = 0.444\), \(0.333^2 = 0.111\), total 0.556; \(0.444 / 0.556 = 0.80\). (Exactly: ratio 2:1 becomes 4:1, so 0.8.)

3. The post-training menu

Method Training signal
SFT target responses (demonstrations)
RLHF human comparisons → reward model → RL (e.g. PPO)
RLAIF AI preference judgements → RL
RLVR a verifier checks the answer / runs tests → RL (DeepSeek-R1)
DPO chosen/rejected pairs directly, no reward model, no RL loop

DeepSeek-R1-Zero: RL (GRPO) with no SFT first; reflection emerged, but readability and language mixing were poor. R1 added SFT stages. GRPO scores each answer against others for the same question, no critic.

A lab trains a coding model by running each generated solution against unit tests and rewarding passing solutions. Which method is this?

An automatic verifier (tests) gives the reward: RL with verifiable rewards. RLHF would use human comparisons via a reward model.

4. The three knobs and two policies

Knob Changes \(\theta\)?
training (pretraining, SFT, RLHF, RLVR, DPO) yes
decoding (greedy, temperature) no
inference-time compute (more reasoning tokens, samples, checking) no

Worked examples in the prompt change the output but not the weights. A model-level policy is a distribution over next tokens; an agent-level policy chooses environment actions from history and goal. A tool request is just text until an executor runs it.

Poll 3: which of these updates the model’s parameters \(\theta\)?

Only training changes \(\theta\). The others are decoding, context, and inference-time compute.

Stage test

A model uses greedy decoding. The temperature is raised from 1 to 2. What happens to its output?

Temperature reshapes the distribution but never changes which token ranks first, and greedy only looks at the top token.

Why is next-token pretraining not reinforcement learning?

Both use networks and gradients. The difference is the signal: given targets from text vs reward from acting.

What does the causal mask in a GPT-style transformer do?

At position \(t\) the prediction may depend only on \(x_1, \dots, x_t\).

Labellers repeatedly pick the better of two responses. A separate network learns to predict their choices and is then used as the reward for PPO updates. Which method is this?

Human comparisons → reward model → RL: RLHF. DPO would train on the pairs directly, with no reward model.

What distinguishes DPO from RLHF?

Both use preferences; DPO skips the reward model and the RL optimisation.

What was notable about DeepSeek-R1-Zero?

R1-Zero started from DeepSeek-V3-Base with RL only. Its readability and language mixing were poor, which R1 fixed with extra SFT and RL.

Select all that leave the model’s weights \(\theta\) unchanged.

Only SFT is a training update. Context, decoding and inference-time compute don’t touch \(\theta\).

At \(T = 1\) the next-token probabilities are 0.5, 0.3, 0.15, 0.05. What is the first token’s probability at \(T = 0.5\)? (Three decimals.)

Square: 0.25, 0.09, 0.0225, 0.0025; total 0.365; \(0.25 / 0.365 = 0.685\).

The true next tokens received probabilities 0.5, 0.25 and 0.8. What is the pretraining loss \(-\sum \ln P\)? (Two decimals.)

\(0.693 + 1.386 + 0.223 = 2.30\).

An LLM outputs book_flight(id=441). What has happened in the world?

Model-level policy (tokens) ≠ agent-level policy (actions). Acting needs an executor and permissions.

Which is the best description of Shannon’s 1948 experiments compared with modern LLMs?

Continuity: generate by repeatedly predicting the next symbol. Difference: learned distributed representations and long context, not count tables.
