Planning and orchestration

One loop is enough to find a flight. A twelve-day, five-city tour with hotels and visas needs more structure. The choice is the old one from weeks 2 and 3, react or deliberate, and the rule is to pick the cheapest architecture that handles what must be decided at run time.

Kind: LLM-based agent.
Week: 6, Part IV (slides 38 to 43) and the coding-agent comparison (slide 47).
Book: Wooldridge ch. 4 (BDI) for the analogy only. Optional: Yao et al. 2023 (ReAct), Shinn et al. 2023 (Reflexion), Huang et al. 2024 (LLMs cannot self-correct reasoning yet), Anthropic’s multi-agent research system (2025).
Techniques on this page: BDI vocabulary for LLM agents, three control patterns, choosing the cheapest adequate architecture, orchestration patterns and their cost, reflection.

The problem it solves

The passenger now wants a five-city conference tour with flights, hotels near venues, visa checks and a $6,000 budget (slide 38). A single step-by-step loop may drift, forget constraints or run out of context. More structure helps, but every extra component costs tokens and can fail. Week 6 ends by tying LLM agents back to the BDI, reactive and hybrid architectures of weeks 2 and 3.

Words you’ll hear

Word Plain meaning
ReAct reason + act, incrementally: observe → choose next tool → observe again
plan then execute generate several steps first, then carry them out and check
hybrid (control) plan, act, monitor, replan, with deterministic checks of the plan
planner–executor one part plans, another executes the steps
orchestrator–workers an orchestrator delegates sub-tasks to sub-agents (often in parallel)
sub-agent another agent instance with its own context
critic / reflector an extra loop that reviews an output
Reflexion verbal feedback stored in episodic memory to improve later attempts, no weight change

Technique 1: BDI vocabulary for LLM agents

Problem it solves: links week 6 to weeks 2 and 3 (slide 39).

BDI term In the LLM-agent trace
beliefs \(B\) available flights, latest fares, what tools reported
desires / goals \(D\) find an acceptable flight under the constraints
intentions \(I\) commitment to the delegated objective, perhaps a selected option
plan \(\pi\) search → check → present options → stop
commitment strategy (blind / single-minded / open-minded) how often the harness lets the model replan

Where the analogy breaks. Text in a context is not a logically consistent belief base (it can hold $490 and $560 for the same flight). A plan the model writes is not automatically a persistent intention unless the harness stores and enforces it.

Technique 2: three control patterns

Problem it solves: decides when the deciding happens (slide 40).

Incremental (ReAct-like) Plan then execute Hybrid
observe → choose next tool → observe again generate several steps, then carry them out and check plan, act, monitor, replan; deterministic checks of plans
responsive; may drift without explicit state clear structure, fewer model calls; plans can go stale flexible, but more engineering

The old tension returns: reactivity vs deliberation (subsumption vs BDI, week 3). One modern answer: let the LLM propose plans and let external verifiers check them, so intelligence is split between learned and engineered parts (like a hybrid architecture’s layers).

Technique 3: the cheapest adequate architecture

Problem it solves: don’t build an orchestra for a solo (slides 41 to 42). Ask one question: what must be decided at run time?

Slide 41’s three tasks.

Task Pick Why
A. Every morning check the SFO → NYC fare for 18 April; email if below $450 workflow nothing to decide: fixed steps and a fixed rule
B. Today: find a flight after 10:00 for at most $500; don’t book single agent loop which search next depends on what came back
C. 12-day tour: Boston, Toronto, Chicago, Denver, Seattle; flights, hotels, visas, $6,000 orchestrator with sub-agents (or planner–executor) breadth and parallel work; too much for one context

Technique 4: orchestration patterns and their cost

Problem it solves: every pattern buys something and pays for it (slide 42).

Pattern Who decides the path Fits Main cost
workflow, chain, routing the program task A rigid when the unexpected happens
single agent loop the model, step by step task B drift without explicit state
planner–executor plan first, then execute long, structured tasks stale plans; needs replanning triggers
orchestrator–workers orchestrator delegates to sub-agents task C: breadth, parallel work many more tokens; coordination failures
critic / reflector an extra review loop checkable outputs cost; speculation without new information

A sub-agent has its own context, so delegation is also a context-management tool. Anthropic reported its multi-agent research system used roughly 15× the tokens of a chat. More components need not help a simple task.

Technique 5: reflection

Problem it solves: learning from mistakes without retraining (slide 43).

The loop: attempt / action trace → feedback / observation → critique / revision → lesson stored in memory → next attempt. Reflexion uses verbal feedback and episodic memory, so behaviour changes without changing the weights.

Self-critique without new external information often fails to improve reasoning, and can make it worse (Huang et al. 2024). Ask of every extra loop: what new information does it bring? A test result or a tool error is new information; the model re-reading its own answer usually isn’t.

Technique 6: the coding agent has the same parts

Problem it solves: shows the map is general (slide 47).

Component Airline clerk Coding agent
LLM chooses searches and fare checks chooses files to read, edit, test
context builder task, candidate flights, policy passages task, relevant files, test output
control and dispatch validates calls; book_flight not exposed validates edits and shell commands; asks permission
tools search_flights, check_fare read/edit files, run tests, shell, code search

state and memory fare history, policy index progress notes, version history, code index
orchestration multi-city planner sub-agents exploring the codebase in parallel
